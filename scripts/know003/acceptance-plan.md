# KNOW-003 独立验收预期

本轮核对 KNOW-003-T01、KNOW-003-T02 和完整场景 A11。主跑和独立复跑使用同一冻结提交，分别启动独立 DSH Home、Chrome 和 SQLite。手工流程和模型负例只用回环及合成资料。正向主跑和独立复跑各允许一条经过固定检查的合成请求，通过锁定 Host 的同一原生适配器访问用户授权的词易模型。记录真实请求和本地模型夹具的不同证据范围。

## 夹具与证据

- 管理员 A、普通成员 B 各有独立浏览器会话。A 导入 Markdown V1，正文含「五次采样均值可减少温控告警误报」和唯一标记 K-043-V1，用实际 Reader 选区生成证据 E1。另建一条独立证据 E2 用于纠正。记录来源 ID、资料版本、序号、UTF-16 位置和原文/选区哈希，通过实际引用入口核对原件。
- A 创建并确认软件工程领域的 solution S1–S4、case C1–C4、concept K1/K2，以及异领域 concept X。B 另建确认自己的 S-B/C-B。A 仅授予 B 对 E1 资料的读权限。提前确认 B 能读 E1 和 S-B/C-B，A 的 C1 和 X 不可见。端点均用原创条目，使撤权测试只作用于证据。
- 在 /knowledge/v1 下走 GET /ontology/types、GET/POST /ontology/relations、POST /ontology/relations/{id}/review，以及 POST /ontology/proposals 实际模型入口。详情、历史、证据路由按最终冻结契约。每次拒绝记录 HTTP 状态和错误码，比较关系、修订、证据和幂等回执的完整行前后相等。业务数据通过产品写入，SQLite 只读观察。保留浏览器截图、Git/入口/runner/夹具哈希、命令、退出码与外部推理计数。

## T01 关系规则与访问

1. A 在浏览器选 S1 solves C1、E1，点击提交。HTTP/SQLite 仅有一条 S1 → C1，固定规则版本、证据坐标/哈希及提交人。显式确认后切换图与列表，核对同一个关系 ID、revision、正确箭头与相符状态。点 E1 返回 Reader 的固定选区。
2. HTTP 读取规则快照，验证 solves 为 solution → case，depends_on 指向 concept，compares 为同类型对称规则。其余起点、领域和自环策略从冻结规则取得。逐一提交反向 solves、跨域或错端点类型、规则禁止的自环、同向重复、无证据和随机证据 ID，均明确拒绝且没有行变化。另提交一条合法 depends_on。提交 K1/K2 的 compares 后交换端点再提交，核对对称关系只保留一条事实。
3. B 用自己的 S-B 和可读 E1，尝试指向 A 的 C1。与随机不存在目标对照，响应应为同类安全 404。响应、列表、图和错误提示不应露出 C1 的代号、标题、正文、作者、证据或计数。B 查询 A 的关系详情、历史和审核也不能读取或写入。A 的合法读取继续正常。
4. 原样重放成功写入得到同一关系和 revision，行数与数据不变。相同幂等键替换端点或证据得到 IDEMPOTENCY_CONFLICT。以同一 revision 进行两次不同审核，第一条成功后另一条得到 REVISION_CONFLICT 且数据不变。重启 Host 后核实边、图表、历史和 SQLite 外键。

## T02 实际模型调用、人工审核与不可变证据

1. 启动真实 DSH Host 和受控 LlmAdapter。实际 Chrome 从可读的 S2/C2、E1 触发模型。适配器断言收到预定规则与本次允许的端点/证据，只可输出规则 ID 与简短理由或依据不足。端点与证据由服务端固定。HTTP/SQLite 须有服务端标记的 AI proposed 记录，保留请求人、适配器来源及固定证据。图/列表都能区分建议和已确认事实。公开记录仅保留模型证据的计数、状态和必要哈希。
2. 用受控适配器依次返回非法反向、允许集合外的端点或证据、无证据、未知字段、伪造确认者或确认状态。每次无关系、修订、证据及回执新增。浏览器自行传 proposal_actor=ai、state=confirmed 或 reviewed_by 也得不到可信身份。请求一开始即包含未授权端点时，模型 dispatch 数保持零。
3. A 在 Chrome 实际确认 S2/C2，拒绝 S3/C3，对 S4/C4 将证据 E1 纠正为 E2。确认者来自真实会话，时间来自服务端，拒绝不会成为事实。纠正追加 revision，旧建议完整行不变，保留旧端点、证据、提出人、类型规则版本和时间。未显式确认的纠正仍以待确认呈现。B 知道 ID、revision 和幂等键也不能审核或从原回执读取受限内容。
4. B 以 S-B/C-B 和可读 E1 触发模型。等适配器进入等待屏障后，A 撤销 B 的 E1 资料读权限。确认 B 的证据读取已经返回 404，再让受控适配器返回原合法 JSON。提案应安全失败且没有任何业务写入。若端点在模型等待期间可修改，再用两标签改变端点 revision，旧建议不能被无提示绑定到新端点。
5. A 导入同一资料的 V2 并替换唯一标记。旧关系历史仍保留 E1 和 V1 的坐标/哈希，旧证据链接回读 V1。若冻结写请求包含来源坐标/哈希，提交 V2 和 E1 的错配或伪造值应拒绝并无写入。使用过时的关系 revision 审核应冲突。完整来源删除与全量待复核生命周期归 A12/A45。

两个义务和 A11 均须有实际测试记录，浏览器所见与 HTTP、磁盘一致。本地模型夹具的负例与真实外部正向调用分别取证。F13 关联完整 A11，F14 尚需 A12/A45。
