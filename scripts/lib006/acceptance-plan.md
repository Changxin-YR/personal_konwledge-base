# LIB-006 整本、分章与原书页码

`SEARCH-001` 已通过。P02、A06 的完整验收必须使用合法真实大 PDF；合成数据只能验证输入、调度和故障约束。

| 用例 | 实际路径 | 可观察结果 |
| --- | --- | --- |
| LIB-006-T01 / P02 | 用真实 Chrome 从资料库上传同一真实整本；后台至少发布一章后打开一个确定物理页；中途取消、重启 Host、再继续。 | 上传原件与原始 SHA 一致；已处理页先可读、可检索，未处理/待复核/失败区分；停止期间不再发布；续跑不重复已完成页，入口保持响应。给出冷启动、首次可读、总耗时、峰值内存及失败范围。 |
| LIB-006-T02 / A06 | 对同一原件独立走分章导入，预先定好有名页段；抽查首、中、尾、章节边界及文字/表格/图片/代码所在页。 | 每个结果仍绑定原书物理页和具体资料版本；进入章节的第 1 页不被误标成整本第 1 页。比较整本与分章的持久文字、状态、图片/复核和检索引用，任何差异明确记录。 |
| 负例 | 非读者猜页面 URL；无编辑权启动；重叠、逆序、越界和空范围；活动任务中改范围；取消后旧租约提交。 | 先检查 ACL 与可信版本；错误不写页不改变已有计划；旧租约不能发布；未选择页不被伪标为已处理。默认整本和 A07 的按页重试必须回归。 |

工程取舍：同一导入版本只保留一份原始 PDF；分章是对应原件的一组持久范围，不切写或重编码原始 PDF。范围使用从 1 开始、两端包含的物理页码；界面分别表示未选择、未处理和待复核。先确定真实输入、哈希、页数、体量、文本类型和固定章节边界；保持样本在 Git 忽略目录，不上传原件或数据库。若没有接近要求的真实文件，保留验收状态并推进安全的实现、测试或其他依赖就绪单元。
