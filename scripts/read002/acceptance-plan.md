# READ-002 目录、书签与阅读恢复

依赖：READ-001 候选 `fdac3b02fc5ac42eabef72374aee9b7050c942e3` 已通过。用例当前均为 `NOT_RUN`，不代表 P03 或 A09 整场景通过。

| 用例 | 输入与操作 | 必须观察的结果 |
| --- | --- | --- |
| READ-002-T01 | 导入包含至少两个明确章节的 PDF 和 Markdown。目录跳到第二章，新建个人书签，再导航到其他位置。重启 Host 并用全新 Chrome 上下文从不带位置参数的同版链接打开。 | 恢复最后成功保存的本人位置；打开书签回到书签的固定版和位置。显式 `unit` 或引用链接优先，不被恢复结果覆盖。目录只展示已知的 PDF 书签与 Markdown 标题，不从 PDF 文本猜测章节。书签可删除，重启后不再出现。 |
| READ-002-T02 | 所有者和只有 `read` 的读者用独立浏览器上下文打开同一资料同一版本，各保存不同位置并新建书签；交换读取或删除书签请求，随后撤销读者授权。 | 每人只看到本人的状态，不受另一用户或管理员身份影响。可读共享原文不意味着书签公开，也不要求源资料 `edit`。越权、撤权后的读写返回不披露正文的拒绝，原有个人记录不串户；已开页面清理可见目录和书签。 |

- **版次负例：** 同资料发新版、Word 同版重转换，或保存的位置已不再可靠时，不把旧状态套到新页。保留原书签与版本身份；读者可明确选择仍可访问的旧版，或从新版安全起点开始。阅读模式切换不改变位置。
- **并发与持久化：** 同一用户两个标签页依据服务端 revision 更新，迟到更新不能覆盖新状态。保存失败不谎称成功。验证新增 SQLite 迁移对已有 v15 引用与资料无损，故障可回滚；重启回读用业务 HTTP 与 SQLite 双证核实。
- **范围：** 仅目录、个人书签、阅读位置。全文检索、批注和术语练习分别由其后续单元验收。Chrome 保留正常、失败和权限场景截图；独立角色在冻结候选上实跑。
