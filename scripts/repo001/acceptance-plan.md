# REPO-001 GitHub 固定提交接入验收计划

前置：FND-004 / FND-006 已验收。GitHub 为当前单元唯一平台；完整 A19 的 GitLab/Gitee、AI 写拒绝不得用 GitHub 结果替代。使用已有获准的合成公开仓库或小型公开测试仓库；不上传原件、个人数据或凭据，不执行仓库任何内容。

## T01 固定来源可复现

1. 用真实产品页面连接仓库，在独立 Host 中以只读请求解析分支或标签到完整 SHA，读取该 SHA 的树及选中文件。用真实 GitHub 响应另行交叉核对 commit、路径、blob SHA 与文件内容；夹具只能补负例。
2. 已完成的导入继续绑定原 SHA；修改输入引用、刷新页面或重启 Host 不能把保存的树和文件悄悄重定向到新头。验证持久记录、独立会话重读和固定来源链接相符。
3. UI 不收明文凭据。凭据可引用现有原生安全入口，由 Host 获取；API、SQLite、测试摘要和截图只留引用与配置状态。没有获准私库测试入口时不声称已验证私库真连接。

## T02 拒绝、限额和仓库内容隔离

1. 另一个有效账号无权读连接、树或文件；不存在/无访问权限的远端不返回可误作成功的数据。拒绝伪造账号、非 GitHub 目的地、重定向、非法对象/路径、截断或过量树/文件；验证不留部分可见快照。
2. 通过合成恶意 README、控制字符路径、符号链接或子模块测试：前端当纯文本，Host 不执行、不加载外链、不安装、不切到子模块，也不调用写 API；网络证据仅含批准的只读 GitHub 路径。检查解析、证书、HTTP 失败和取消后无错误成功回执。
3. 冻结后独立重跑真实 Host/Chrome/SQLite；记录授权来源、请求类型、SHA 和回读差异。验证通过仅记录 REPO-001 T01/T02，A19 另行集成补验。
