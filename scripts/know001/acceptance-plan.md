# KNOW-001 独立验收预期

依据 F10、KNOW-001-T01/T02、READ-002 位置与版本、数据契约 §4.2/5.1、API 契约 §3.3/4.1–4.3 和 A10/P03。完整术语到练习、首次答案、多用户作答、复习仍由 LEARN-006 等后续单元完成。本轮将 P03/A10 保持 NOT_RUN。

## 实际产品入口与取证

- 冻结候选和构建后，先记录候选 commit/tree/source、bundle、runner 和合成资料 SHA-256。主跑与独立复跑分别启动锁定的真实 DSH Host、Chrome 和 SQLite，使用新测试身份、新 profile 及同一合成资料。所有读取、选词、保存、返回位置和错误都走实际产品路线。
- 拟定最小入口是读页批准文本选区后的「解释术语」。结果在当前上下文展示语境、通俗解释、专业定义、易混概念和可打开的来源。显示可解释的「来源不足/无法核验」，允许结束查询，允许明确保存或编辑个人补充。选择的项目和版本不由 URL 返回参数越权改变。
- HTTP 以 /knowledge/v1/terms/explain 的实际实现为准。建议输入使用 Reader 可复现标识（asset_id、version_id、ordinal、可选 conversion_id、UTF-16 start/end、source_hash），可附允许的 request_id 或 actor 校验值。不要接受客户端自行提供的权威语境、引文正文、归属/角色。服务端临时生成结果携带已核验锚点与 save handle 或同等绑定；保存单独 POST 按幂等键执行，不重复推理。具体路由、状态码和字段随冻结实现核实，不能放松这里的状态断言。资源隐藏优先沿用 Reader 的 404/ACL 语义。
- 用当前经过授权的 DSH native 路由进行正向真实解释验收，实际 provider/model 和允许的请求限额在启动前确认。FND-005 旧许可绑定其旧候选和对象读写；本单元用当次候选、合成片段和独立的实际许可/预算证据。每个真实运行只需两次解释，两个固定语境各一次，合成资料不含私密数据。禁止自动重试或替换模型，记录实际请求与出站数量、用量和费用上限；夹具负例另证。

## T01 · 相同术语在两种专业语境中

1. 导入相邻 Markdown 两段，分别打开数据库和程序设计段落。两次均用真实浏览器选择相同的「索引」两个字，且该字在每段出现多次。用 DOM Range 选定真实后一次出现位置，记录服务端正文、真实字符串 start/end，而非全文 indexOf。emoji 位于范围前面，用来验证 UTF-16 数值不同于 Unicode 码点数。按实际 Reader 逻辑求 ordinal，不写死标题或块编号。
2. 从实际选择触发的 HTTP 和页面核对专业和通俗解释均存在且清楚区分语境。数据库段解释的是用于检索记录的结构，至少响应「结构/查询/查找」类概念，并以合成正文的 B-tree、查找记录或减少扫描作为可复核依据。数组段解释的是元素的位置编号，并可用原文 0 或第一个元素解释；查询优化和 B-tree 不是此段定义的依据。可以用人工核对与概念集合，不要求逐字匹配模型措辞。易混项要说明与另一含义的差异，不把同形项混成一张答案。
3. 所有证据都用服务器可读回的 asset/version/ordinal/range/hash 或等价固定 locator，从 UI 打开原处。断言返回 quote 与源文本按记录范围切片相等，且两条解释的固定范围不同。多次出现同词时必须准确高亮后一次。模型不得提供未经验证的外链、页码或跨段引文。在每张卡片生成后、显式处理之前，检查术语、版本及引用持久行相对请求前没有新增。为避免额外真实调用，顺序可为解释 A 并核对零写入 → 保存 A → 解释 B 并核对零增量 → 放弃 B。允许独立的审计、用量记录。
4. 附真实 Chrome 两张截图、已授权的实际模型路由/出站和固定锚点。模型输出一旦和已有证据不相容，保存失败记录；不可通过手工改成期待措辞来声称真实推理通过。用合成测试资料和受控概念集合减少不必要的重跑。

## T02 · 保存、放弃、原位置与异常

1. 在数据库段的临时结果仍有效时点击显式保存，普通学习者乙有同资料阅读权但无法看到甲的个人术语。XHR 成功后读取列表/详情和 SQLite，确认单一个人术语和可定位来源版本、选区以及确实来自该次解释的内容。若补充编辑属于当前候选，改补充后核对术语源锚不动。重放同键保留 ID，无重复术语和引用。将同一临时结果用不同用户、不同 source hash 或 falsified owner 保存，应拒绝，零写入。候选若支持额外的个人积累范围，以批准的业务程式为准。
2. 对数组结果点击关闭/返回，页面保留实际阅读单元及浏览位置。先令状态书签/位置落盘，再从普通阅读入口刷新位置恢复，并重启 Host 和 Chrome 用原账号复核。保存的数据库术语链接能打开原处，数组无持久记录。导入同一资料的 V2 后确认已保存卡仍指向 V1 和原选区。若采用额外固定 Word conversion，同样不得漂至最近转换。不要要求在重新登录后恢复未保存的临时结果。
3. 对短到无法决定含义的「索引。」、错误源 hash、超出页段范围、拆分 emoji、错误版本/转换、无已解析正文分别执行真实业务 HTTP/界面请求。找不到来源、源未就绪、明显不充分时应显示明确状态，不出现编造来源、可保存卡片或术语/引用增量。可在派送前判断的非法与越权负例应为零模型派送；语义不足可用受控适配器产出语义不足证明。
4. 同一已授权账号用实际 UI 发出 A。通过一次受控响应门限暂停并保留真实的 A 结果，切到 B 段/选新范围，得到 B 后交付 A。B 的卡、source、保存按钮和阅读位置不能被迟到 A 重绘。再用独立账号在可见页面远程撤销甲对共享资料的授权，用受控适配器将响应置于撤权前后。服务端不返回受限正文或已生成的源绑定说明，不允保存、重放或读取受限卡正文。页面已显示资料和卡则清除，若请求晚到也不可重新出现。核对尚有权的对照来源仍正常。另用业务账号切换或 Reader 授权失效触发同样清理。记录是否为响应延迟、服务端执行屏障或业务授权操作，保持各证据分开。
5. 无原生默认模型的真实隔离 Host 仍能登录、读源、翻页和读取近期位置，术语解释显式不可用且零派送。使用独立的确定性适配器验证伪造 citation ID、跨页/跨资产引用、超长或无效模型输出，以及断开/超时不发布持久结果。测试只对隔离适配器，不发送供应商调用去制造失败。
6. 如有新增迁移，使用带现有 Reader 状态和引用的原 v33 或当前确认的前版 SQLite 验证升级、故障回滚及重跑；旧 checksum 保持。证据至少含来源权限失败和两个语境截图、精确候选、真实与夹具两类的脱敏 HTTP/SQL，及主跑、独立复跑的 PASS/FAIL/NOT_RUN/BLOCKED。
