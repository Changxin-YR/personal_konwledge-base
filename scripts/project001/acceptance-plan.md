# PROJECT-001 项目、成员与派发验收

前置为 FND-004、SHARE-001 已验收。使用隔离 Host、真实业务账号、Chrome 和 SQLite；不调用模型或写真实项目。A51 的约十人竞争留给后续单元。

## T01 / A30 授权派发、标准版本与归属

1. 从项目协作页面新建项目。项目所有者使用现有 SHARE-001 邀请入口，负责人、审核人分别通过各自登录接受邀请。可使用隔离预置的第二管理员覆盖管理员终审选择。读取成员名单只显示当前有效的项目成员。
2. 指定负责人、目标、至少一项可核查标准、绝对截止时刻和审核路径后发布。管理员派发必须有当前项目内的管理员终审，可另设同伴预审；普通协作按指定审核人，不能伪造角色或跳过权限。初始状态 assigned，下一处理人为负责人。个人任务仅可派给自己，不创建项目可见资料。
3. 通过页面改标准。当前任务修订和适用未来提交的标准版本上升一版，原标准、原权重与创建时间仍可读；并发旧修订 409，不能把后续修改套到旧版本。重启后 API、页面和 SQLite 数据一致。正式提交、终审和计分均未属于本单元，不提前写假结果。
4. 历史成功请求的幂等回执只能在当前权限有效时重读。非成员尝试列表、直接读取、伪造派发与修改标准：均拒绝，响应不透露任务标题、标准或数量；本切片不提供认领他人任务的操作。

## T02 真实成员失效与个人隔离

1. 在隔离业务时钟上推进到项目邀请码绝对截止时刻，保持 Host 运行，确认该成员从任务列表和直接链接失权，选人和新派发也拒绝已失权者。
2. 项目所有者可移除非所有者成员。即使该成员有多个有效成员来源也不能继续读任务；不得撤销无关成员或私人资源。旧兑换、旧授权和续期不能使已移除的成员恢复访问；需要明确的新邀请。
3. 同时验证个人任务和私人原件仍归本人、未进入项目。记录删除/撤权审计、SQLite 旧记录和 UI 拒绝结果。冻结后由独立角色复跑主流程、负例和受影响的 SHARE-001 / FND-004 路径。
