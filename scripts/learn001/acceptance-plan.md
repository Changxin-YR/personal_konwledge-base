# LEARN-001 独立验收预期

覆盖 T01、T02 与 A13/A14 的作答基础。在同一冻结提交分别启动隔离 DSH Host、Chrome 和 SQLite 做主跑和独立复跑。只用合成资料、测试账号和回环网络，模型请求为零。A13 仍需 LEARN-002 完成阅读范围快答集成。A14 仍需 LEARN-003 完成个人错题、改题及评价重算。

## 固定夹具

- 管理员 O 建项目 P，通过实际邀请入口分别让普通成员 A、B 加入。第三个普通账号 C 只加入另一项目 Q。O 在 P 准备三种共用题。各学习者使用独立 Chrome context，新建自己的作答会话，使用全局相同的三个题目版本。C 另有 Q 内可正常作答的对照题。
- O 将合成 Markdown V1 导入个人资料并用 Reader 生成固定引用。独立授予 A、B 对资料的读权限，分别验证实际 Reader 能读取引用。题目来源保留引用 ID、资料/题目版本、坐标和哈希。项目成员权限与资料读权限使用不同授权，便于单独撤销。保留单独的自主内容作权限对照。
- 选择题的固定版本的选项序号 对应「限次重试」「无限重试」，前者正确。判断题为「已知上限仍采用无界重试是安全策略」；标准答案为布尔 false。填空题标准答案为 FINITE，配置等价答案「有界重试」；测试全角和前后空白的「 ＦＩＮＩＴＥ 」、配置别名和未列入答案的解释「在时间预算耗尽时停止再次请求」。解析包含仅出现在隐藏答案数据中的唯一标记，如 LEARN001-EXPLANATION。
- 固定候选后用契约中的 POST /knowledge/v1/practice-sessions、GET /knowledge/v1/practice-sessions/{id}/questions、POST /knowledge/v1/practice-sessions/{id}/attempts 和产品实际创建/历史入口。记录候选提交、入口、runner、夹具 SHA、退出码、HTTP 状态、Chrome 证据和 SQLite 行；浏览器行走产品写入，SQLite 只读对照。迁移与写入故障另用独立隔离数据库。

## T01 共用题目与个人首次答案

1. A、B 打开各自真实题目视图，核对两人收到同一题目及版本 ID、题干和选项。会话、状态和作答独立。首次 GET、刷新及 A 提交之前收到的所有业务 JSON、初始 HTML/DOM 均缺少解析、判分规则、填空可接受答案、正确标志及其他人的作答。选项中出现正确文本本身是正常公开题面，检查是否暴露正确标记。
2. A 首次选错，B 尚未提交并刷新。提交响应只在 A 的第一次作答以当前身份、固定题目版本和服务端时钟持久化后返回解析；独立数据库连接在收到响应时读到首答。B 页面不出现 A 的解析、所选答案、编号或结果。B 首次选对得到自己的一条正确记录；A 再答正确恰好追加一条后续记录。两人的首答及 A 的首答时间、原答案和错误状态完整保存，从两个会话/页面和 SQLite 对照，后续正确不覆盖首次错误。
3. 浏览器提交判断题，严格布尔 false 正确。向实际提交接口发送非法类型（如字符串 "false"）时返回输入错误、零写入、无解析。填空测试固定版本所声明的规范化规则和答案别名。合法等价表达判正确；无法用规则确定的开放表达记录 disputed、说明依据，并缺少正式对错结论或正式评价事件。没有人工或模型依据时不得把 disputed 映射为错误。源链接用真实 Reader 打开固定引用精选内容。O 引入 V2 改变源句后，原作答/证据仍引用 V1，产品可标记待复核。
4. 重启 Host，以新浏览器会话分别查询 A、B 的独立历史并复核确定的判分规则版本、首次及后续序号、首次提交时间、题目版本、证据和 SQLite 外键。确认共享题/版本只存一份，未因两个用户作答复制为全局错题。

## T02 安全揭示、重放、并发与撤权

1. A 在另一未答题以直接 API、候选公开的揭示路径和深链接尝试获取答案，均无解析；B 的已作答题不能给 A 的未作答题解锁。使用普通成员凭据访问作者读写入口、读取和写入对方私有会话/历史，或用另一会话/项目题目版本替换当前版本，均拒绝且无泄露。C 和未登录请求不能取得 P 题的受限题干、ID、受限来源、答案、解析、其他人姓名或计数。提交不可信 owner/user/sequence/结果/时间字段无越权效果。
2. 用实际网络在首次提交中途制造回执丢失或精确重放同一幂等键和请求，比较同一 attempt ID、序号、首次时间及全部相关行。同时改变同一键的答案或会话应冲突，既无新行也无额外解析泄露。两个标签以同一预期序号提交不同答案时至多一次前进，另一个 409 或可验证的等价幂等返回。随后按当前序号显式重答才生成下一条 attempt。比较会话、作答、个人状态和回执的行数及内容。
3. 保持 A 的答题/已揭示页面在前台。单独撤销 A 的资料读权限但保留其项目成员资格，验证旧引用读取和题面、解析、来源片段、前台页面与幂等旧响应中的受限内容同时消失。已存储原始记录保持，无法通过题目/答案回执或作者路径重获受限内容。B 与 C 的无关有权路径继续正常。另撤销 B 的 P 成员资格但保留资料读取，验证深链接、候选列表、提交、历史/重放及前台页失去 P 范围内容。检查所有被拒写入零副作用。
4. v39 存储回归使用上一单元冻结 v38 构建真实建立的账号、项目、引用、条目、关系及审核/回执，记录完整旧行。故障注入到迁移记账前，证实 schema、版本账本、数据及外键无改变；正常迁移两次启动恰有一条 v39 记录。分别在作答写入及回执/个人状态的中途触发 SQLite 错误，验证无首答、序号或提前揭示，移除故障后同键只提交一次。故障注入限独立测试库。

以实际响应及磁盘事实判定两条工作单元义务。A13/A14 完整状态维持 NOT_RUN。
