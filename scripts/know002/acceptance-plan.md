# KNOW-002 独立验收预期

覆盖工作单元 T01/T02 和 F13/F14 的知识条目、来源和人工确认部分。A11 属于 KNOW-003，A12 属于 LIFE-003。使用冻结候选在两个独立的真实 DSH Host、Chrome、SQLite 测试目录做主跑和独立复跑。只用回环业务请求和以下合成数据，模型出站为零。记录精确 commit、源码树、bundle、runner、命令、HTTP、SQLite 行和 Chrome 可见结果。

## 固定合成输入

- A 为初始化的业务管理员，B 为普通成员，分别使用独立 Chrome context。A 从实际入口导入 audit.md V1，正文为「温控算法以过去五次采样的平均值作基线。固定证据标记 K-042-V1。超过阈值时才记录告警。」用实际 Reader 选择「固定证据标记 K-042-V1」生成引用。记录 asset ID、version ID、ordinal、UTF-16 start/end、source hash、quote hash、citation ID，以及真实来源链接。用 HTTP、持久行和源文本验证两个哈希。
- A 新建私人笔记「原创温控复盘」，正文「我建议先记录基线，再比较阈值，最后复查告警。」记录 note ID、根节点正文、revision 与内容哈希。B 另建无引用且完全独立的私人笔记。
- A 按真实邀请码路径把 V1 的资产读权限授予 B。独立验证 B 可以读固定资料和引用，仍无法读 A 的私人笔记。使用项目邀请时单独记录资料权限，权限测试只撤资料读权，不撤账号会话。全程不直接写 SQLite。

## T01 建条目、证据与人工确认

1. A 从实际知识库入口创建「温控基线」概念，选软件工程领域，输入可区别于原资料的解释，附真实 citation ID。创建返回草稿或待确认，页面区分解释正文与引用来源。HTTP 和 SQLite 核对条目 ID、类型、领域、服务/拥有者、版本 ID、作者、精确旧来源坐标与哈希。若预览显示原文，从当前受权的原始引用读取即可。引用原文未被复制到自由正文或公开记录。
2. A 另用实际笔记入口或知识表单从私人笔记创建「原创温控复盘经验」。页面区别真实笔记来源与资料摘录。核对源 note ID、当时 revision、内容哈希和可打开的链接。B 即使知道该 note ID 或哈希，也不能用它创建条目、读 A 的条目、确认或编辑其版本。
3. A 从 Chrome 显式确认首条知识记录。确认前后各有独立不可变版本或清晰追加的确认事件。当前状态成为已确认，确认人来自真实会话，时间来自服务端。旧快照保留原正文、来源和状态。请求中的 owner_id、confirmed_by、任意来源 URL 或自由引文被拒绝，或按契约不作为权威字段。B 对 A 的知情记录进行直接详情、旧版本及确认请求，均不得得到正文或写入。

## T02 纠正、旧版本与撤权

1. 从两个标签对已确认的资料条目按同一 expected revision 提交不同正文或定义。只能有一个成功，另一个 409，当前指针恰前进一次。独立查看上一已确认版本和实际 SQLite 行。编辑作为新版本等待真人确认，除非用户走明确的「保存并确认」操作。重复同一个幂等请求返回同一版本 ID，改变请求内容或使用旧 revision 后不能追加版本。向写接口提交未知来源 ID、另一个资产的版本/转换、不可读笔记或伪造来源哈希时，零新增版本、来源、回执和指针改动。
2. A 通过产品对 audit.md 导入 V2，改掉标记及原句，保存真实新版本 ID。打开原知识条目的旧版本及链接，应仍指向 V1 原始选区并回读 K-042-V1。再修改 A 的私人笔记。旧笔记来源记录仍为旧 revision 与旧哈希。现有系统没有持久的笔记旧正文时，将来源显示为已变化或待复核，不得以当前笔记正文冒充历史证据。
3. B 在有读权限时通过实际入口创建并确认自己的资料衍生知识条目，其中含独特标记「受控派生 K-042」；另建一个与资料无关的原创对照条目。若产品从带引用笔记取材，再建 B 的私人笔记并绑定此资料引用，验证由其形成的条目仍受原资料读权控制。持续打开 B 的受控条目，然后 A 远程撤销资料读授权。B 应清屏或显示来源不可用。通过真实列表、详情、版本历史、源预览、确认、编辑和旧幂等回执重放逐一验证无受控正文、摘录、旧标题/来源地址等内容泄露，写入零副作用。B 独立原创仍正常，A 的原资料仍可读，A 的管理员角色不会使 B 的私人条目归 A 可见。
4. 重启 Host，并用新的浏览器 context 读回有权条目。对照 SQLite 的当前指针、完整版本链、来源坐标、确认人、修订前后行与外键。新增迁移的独立存储回归使用包含旧 note、citation、saved_terms 的 v36 数据，模拟失败后确认版本账本和旧行无变化，然后正常重跑。迁移与生命周期未完成的场景分别留证。当前单元结论仅填 T01/T02。

## 驱动约定

使用计划里的 POST /knowledge/v1/knowledge-items 和 POST /knowledge/v1/knowledge-items/{id}/versions，以及冻结候选的列表、详情、历史 GET 和确认动作。用一次实际发布确定具体 JSON/状态，不接受客户端字段替代持久确认人或权威 source。测试候选必须确实建条目、写版本和对照磁盘，不能只截图或模拟响应。
