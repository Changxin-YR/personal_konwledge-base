# SHARE-001 邀请码授权、同刻到期与权限分离

依据 [执行状态](../../config/execution_state.json)、[工作单元](../../config/work_units.json)、[需求矩阵](../../config/requirements_matrix.json)、[数据契约 §2.2、§3、§11](../../docs/plan/04_DATA_AND_STATE_CONTRACTS.md) 和 [A34](../../docs/plan/07_ACCEPTANCE_MATRIX.md)。依赖 `LIB-001`、`FND-004`。`SHARE-001-T01/T02` 和完整场景 `A34` 分别记结果；本文件只定义待执行验收。`P13` 由 `LIFE-002` 用真实回收、预览、恢复和重新确认旧分享流程补验；本单元的到期、撤销或拒绝删除用例不替代它，也不据此将 F31/F32 标为完整通过。

## 环境与观测

- 每次主跑与独立复跑均用冻结候选、锁定 DSH、真实 Chrome、新的隔离 Host、SQLite 和输出目录。真实业务登录至少四个身份：所有者 O、成员 A/B、未获授权的 C。Chrome context 分开，不能用上游 owner cookie 代替业务身份。用真实导入的合成文档、一个私人对照文档及另一个项目对象验证授权范围。除当前导入若不支持选项目所需的最小项目文档绑定夹具外，不用 SQL 创建业务数据；单列该夹具，邀请码、兑换及授权变化全部走真实业务接口。以独立只读 SQLite 连接比对前后状态。
- 在隔离 Host 注入可控业务时钟，不修改 Windows 系统时间，也不允许请求头、查询或请求体提供判权时间。记录实际服务端判权的 UTC 毫秒，确保邀请、授权、成员资格及实际读写路径使用同一时基。若测试时钟也推动会话到期，跳时后重新登录并先确认 `/me` 成功，避免把登录失效误判为授权截止。验证浏览器倒计时与断网隐藏时同步控制 Chrome 应用时钟；只推进浏览器时间不算服务端验收。
- 用真实业务 UI 发码、兑换、阅读、编辑、预览及确认续期和撤销；直接 HTTP 验证隐藏按钮以外的路径、时间边界与竞争，再读 SQLite。码原文仅创建时展示；数据库、后续列表及审计不得包含明文码。脱敏截图、录屏和请求证据，不记录原码、密码、会话 cookie 或私人正文。

## T01 / A34：默认七天与精确截止

1. 在 `T0` 通过 Chrome 签发只读和编辑两种默认邀请，范围为同一文档；只读只有 `read`，编辑路径应产生实际读取和编辑所需的显式权限，不包含管理。用项目文档验证成员门槛；若候选也支持显式分享个人文档，用不同文档验证只有有效兑换者可读，未分享的个人文档仍隔离。另保留未用的邀请码测试截止，使用自定义时长证明并非固定七天。核对 UI 展示对象、权限、带时区的绝对截止，以及持久化 `issued_at = T0`、`expires_at = T0 + 7×24h`。A/B 兑换前均无目标文档权限。
2. A 在签发日兑换只读，B 在 `T0 + 6d` 兑换编辑。界面显示 B 只剩一天，两组派生授权的 `source_invitation_id`、绝对截止 `E` 分别与其源邀请一致，而不是 `redeemed_at + 7d`。同一用户重试返回既有兑换及授权，不重复占用名额；任何回执都不能绕过当前权限或复活已撤销授权。
3. 在 `E−1ms`、`E`、`E+1ms` 使用有效业务会话，测试实际文档、固定版本阅读和带合法 `revision` 的编辑。到 `E` 即拒绝兑换及仅由这些邀请提供的访问；未用码要有剩余名额，排除容量错误。确认所有者仍可读、对象未误删。已开预览到期后不得经刷新、历史返回或缓存再次暴露；离线时已知 `E` 到达仍隐藏受控预览，重连重新验权。`read` 本身不等于 `export`。

## T02 / A34：竞争、发行者失权与独立授权

1. 限额为 1，A/B 用两个业务会话在 `E` 前并发兑换同一码；记录服务端请求确实重叠。恰好一方成功，失败者无权限/兑换行，计数为 1，SQLite 只有胜者的一组授权和成功审计。再测试同一用户两个会话并发及同键重试，只占一次。另用测试屏障让两个请求在 `E−1ms` 进入、到 `E` 才进行事务内判权；不得新增授权。再测一笔确实于 `E` 前提交、另一笔在 `E` 判权被拒；前者所得授权也在 `E` 失效。屏障只控时序，不替换 ACL 或事务。
2. 先证明编辑者能完成真实编辑，只读者用有效修订编辑被拒。编辑者用合法请求尝试删除原件、签发/转邀、通过直接授权口给他人授权、改变分享范围、预览或提交续期和撤销。HTTP 必须拒绝，且对象状态/修订、邀请、授权和成功审计不变。普通项目成员或系统管理员标签不能打开私人对照文档；目标 ID 或项目 ID 不能将权限带到别的对象。
3. O 分别给 A `manage_share` 和邀请中拟授出的动作；A 在有权时签发。用独立邀请码测试 A 在兑换前只失去 `manage_share`，以及只失去邀请中的某个动作但仍有 `manage_share`。B 均不能兑换；不得占名额、部分发放或写成功审计。有权发行者的对照邀请仍可正常兑换。测试的是失权后不能继续授予；不擅自推定早已成功的兑换会连带撤销。
4. 对同一成员和同一对象验证独立来源：两个邀请或邀请加直接授权同时提供同一动作；再用不同来源显式组合 `read` 和 `edit`。先令来源一失效，再用另一组对象反转顺序；只减去对应来源，其他来源的截止和历史不变，最后一个匹配来源失效才拒绝该动作。某授权到期而未撤销后，新邀请仍能独立发放同一动作。项目成员资格过期时，仍有效的项目对象授权不能单独绕过成员门槛。

## 续期、撤销与持久化

1. 准备同一尚有效邀请下两名有效兑换者、一条已撤销的派生授权及一条独立授权。UI 先预览整组续期的旧/新截止和精确影响集合再确认；SQLite 同一快照中源邀请与所有仍有效派生授权同刻更新，已撤销或独立授权不变。续期不改变既有兑换记录或计数；续期后新兑换只新增一次占用，所得授权使用新截止。越过旧截止仍可访问，新截止统一失效。旧修订/过时预览与重放不能覆盖更新或重复成功审计，同一幂等键换请求内容应拒绝。禁止单独延长派生授权；单人续期或原组已过期/撤销须新建邀请及授权，旧历史不复活。
2. 对另一组在截止前预览并撤销，界面明确说明会同时撤销已兑换的有效派生授权。取消预览不写入；确认后原码不可兑换，下一次受控读取和写入立即拒绝，独立授权不受影响。检查已开页面重新聚焦、刷新、历史返回和实际已有的共享索引读取，不得复用失权缓存；不声称能抹除先前已下载或复制的内容。重放不能增加第二次成功审计或恢复授权。
3. 验证创建、兑换、续期和撤销审计，尤其是操作者、源邀请、资源、影响集合、原/新截止或撤销时间，以及同一事务的事件/outbox 和幂等回执。分别在兑换、续期和撤销写入后、提交前注入故障；新连接及重开 Host 后，邀请、额度、派生授权、审计/outbox 和回执均无部分提交，去掉故障后重试只提交一次。运行外键检查；如果新增迁移，用已含项目、成员、对象及直接授权的旧库验证升级、故障回滚和重开。

## 回归与证据

- 基线项目对象要求有效成员资格及显式动作授权；未分享的个人对象仅所有者可访问。对象列表、资料库列表与文档直读各自验证：不能仅凭基线所有者限定的导入列表判定访问权；若候选把受邀文档列入资料库，核对条目和正文都遵循当前权限及其独立来源，不能靠过期的兑换或其他对象授权暴露。回归 `FND-004` 的直接授权、项目角色及过期/撤销，和 `LIB-001` 的导入、固定版本和原件 ACL 等受影响路径。
- 现有直接授权的部分唯一索引按 `revoked_at IS NULL` 占位，不考虑 `expires_at` 或来源。组合授权及过期后重新发放须以独立来源、SQLite 行和审计证明；不能复写旧行或先撤无关授权来迁就索引。
- 保存候选提交、构建入口/runner SHA-256、Host/Chrome 版本、时钟和屏障绑定、请求关联 ID、HTTP 和 SQLite 对照、审计摘要及脱敏截图/录屏哈希。按实测分别登记 T01、T02、A34 与独立复跑的 `PASS`、`FAIL`、`BLOCKED` 或 `NOT_RUN`。结构检查、夹具或旧候选结果不能代替验收，P13 保留待补验。
