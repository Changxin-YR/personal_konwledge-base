# EXPLAIN-002 独立验收预期

起点为已通过的 `EXPLAIN-001` 候选。当前单元把固定提交内的单文件讲解扩展到一组文件、模块边界、实际调用/数据路径、正常与异常业务流程以及设计取舍。A20 的完整场景在本单元收口，工程诊断 P07 与后续修复单元不在本单元范围内。

## T01｜从文件扩展到模块和关键流程

准备一个固定提交快照，至少保存三个彼此有关的源码文件，包含一个入口、一个业务服务和一个持久化或边界适配文件。分别请求模块职责、实际调用/数据路径、正常业务流程和设计取舍。

预期如下。

- 请求只使用当前用户有权读取的固定快照和已保存的文件行段。
- 请求体绑定快照、提交、文件路径、行段和问题，最多发送一次模型请求。
- 模型回答只引用所选文件中的连续完整原文行。每个事实可按文件、提交和行段重新打开。
- 模块职责、文件间关系、正常流程和取舍分别显示，所有可验证判断都引用事实。
- 固定提交的仓库树只作为结构线索。没有代码证据的调用者、异常处理或外部实现进入 limits，不能从路径名或 README 补齐。
- 点击每条事实的回读操作返回相同固定版本原文，页面刷新或 Host 重启后仍可恢复。

## T02｜异常路径、缺失证据和来源变化

对同一固定快照请求异常流程、权限/版本边界和缺失调用关系。再使用越界行段、未保存文件、错误提交、错误 blob、跨用户请求及模型伪造事实进行拒绝测试。

预期如下。

- 模型必须把未知调用者、缺失异常分支或未提供的外部模块写入 limits，不能生成无依据的关系或流程步骤。
- 事实路径、行号、连续原文、提交和 blob 必须逐项核对。任何不一致都返回 `MODEL_OUTPUT_INVALID`。
- 正在模型调用时固定文件发生变化，或会话、身份、服务发生变化，操作拒绝并且不返回源码、答案或引用。
- 其他用户、匿名请求、未保存文件、非法范围和错误版本不泄露仓库树、文件内容或模型回答。
- 失败、取消和来源变化不产生新的持久文件，也不改变固定快照。

## 运行与独立复核

主跑和独立复跑使用不同的隔离 Host 数据目录、业务账号、浏览器会话和固定快照。两次运行均保留请求摘要、答案、关键页面截图、事实回读、拒绝路径、模型调用计数和构建哈希。独立复核不能读取主跑的运行时状态来代替实际操作。

技术门禁包括 `npm run typecheck`、`npm run build`、EXPLAIN-002 专项源测试、`node scripts/verify-plan.mjs` 和 `node scripts/test-verify-plan.mjs`。未实测的 A20 断言保持 `NOT_RUN`，不以结构校验或模型夹具替代真实页面验收。
