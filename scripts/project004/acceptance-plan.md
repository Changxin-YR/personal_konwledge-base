# PROJECT-004 独立验收预期

契约依据为 F32/F34/F35/F44、工作单元 T01/T02、需求基线 §6、§8、数据契约 §7/11、API 契约的复议条目以及完整场景 A32、A33。预期基于 PROJECT-003 候选 0daad20 的任务、提交、裁决链和材料等待实现，须绑定最终冻结候选的真实产品入口。先写 runner，再分别以主跑与独立复跑启动全新 DSH Host、Chrome context 和 SQLite 数据。仅使用隔离时钟及合成资料，所有业务操作走候选真实页面或 HTTP，SQL 用于读回或受控故障验证。

## T01 · 复议及改判、A32 与 P11 事件契约切片

1. 用真实项目邀请创建普通项目 owner、负责人、指定审核人、另一成员，以及获当前项目授权的业务管理员。准备另一项目的管理员与无项目资格的业务管理员做隔离对照。由普通 owner 派发任务，负责人提交带固定验收标准的成果，指定审核人给出最终失败。记录任务 revision、提交 ID、标准版本、提交时间、原裁决逐列、现有 domain event/outbox 和投影基线。普通 owner 未获管理员权限时保持现有限制。
2. 负责人从真实 UI 对生效裁决发起复议，填写原因及可选证据。页面向负责人和授权处理人呈现可追溯的原裁决、复议理由与待处理状态。数据库新增一条复议，链接实际旧裁决和真实负责人。原裁决、原提交和既有任务结果保持原值，关键结论的派生结算依据进入争议/待重算，而非捏造新分数。若候选支持证据链接，检验链接绑定固定版本，跨项目、当前无权证据被拒或按契约隐藏。
3. 在两个独立浏览器/HTTP 会话验证草稿输入和边界。用空理由、伪造主体/任务/裁决链接、非正式同伴预审、已被替代裁决、越权成员、跨项目身份请求开案或处理。每个拒绝核对真实 HTTP 结果、无越权正文、原行和事件/队列零增量。用同键同参重放返回同一复议 ID，无第二次开案或状态变化。用同键改理由及不同键并发面向同一生效裁决开案应得到冲突或复用已有唯一未决复议，不能出现两条有效未决记录。
4. 有项目权限的业务管理员通过真实 UI 审理并把失败改为通过，填新依据与理由。用当前 revision、原裁决和该复议作为绑定。负责人重读页面看到原裁决、已处理复议和新版裁决，且可知哪条判定当前有效。SQLite 原裁决、提交、标准、提交时点逐列不变，新增裁决替代的是当前有效末端，复议链接处理人和新裁决，任务投影与下一处理人一致。若候选支持维持旧判、拒绝复议，状态显式结束且保持裁决效力。若直接纠正遇到该裁决的未决复议，须明确处理或拒绝，不能留下仍指向失效裁决的幽灵未决状态。
5. 从不同会话提交两份针对同一未决复议的竞争处理，恰有一次生效。随后按同键同参、同键不同参、旧 revision、已替代裁决、已处理复议逐一验证重放与冲突；撤销处理人的项目资格后，已有请求凭证也不能继续读受控材料或重放写入。再换合法用户重启读回，原与新记录、处理状态和项目进度投影均一致。
6. 检查复议改判与既有直接管理员改判的触发契约。事务提交后同读新裁决/复议/任务投影、影响作用域的待重算标志，以及一条绑定前后裁决、任务 revision、真实 actor、关联复议和受影响对象引用的版本化事件及对应 outbox。领域事件使用现有 domain_events 与 domain_event_outbox，前者的聚合版本/事件 ID 唯一，后者跟随事务。旧 jobs outbox 强制 job result FK，不为改判伪造作业。事件只保留必要引用。用独一合成片段验证无材料/复议或裁决正文、会话令牌和邀请码被复制到事件。用受控隔离故障卡在业务写入与 outbox 插入之间或插入后、提交前，断言原裁决效力、复议状态、影响标志、事件和 outbox 全部回滚。解除故障后重跑只有一次成功。该步骤只证明事件与状态契约，P11 继续 NOT_RUN，完整日评分、连续低分、提醒和案例联动留给 SCORE-001/REMIND-003 等真实集成。
7. 在最终候选上以已填充的 PROJECT-003 v32 历史实跑升级、故障回滚、解除故障再升级。核对任务/提交/裁决/纠正、旧邀请领域事件、旧 job outbox、schema ledger 与外键完整性。不得改变历史迁移 checksum。

## T02 · A33 材料绝对到期但项目资格保留

1. 在真实项目派发另一项待审核任务。提交原件版本 V1 的受控材料链接并保留独立的项目成员授权。材料所有者通过真实业务 API/UI 仅给指定审核人短期材料 read 邀请，审核人兑领。材料授权用 1 天，项目成员权限用更长期限，确认没有隐式 ACL 或第二材料授权可读。记下服务端 returned expires_at。因为业务登录会话只有 12 小时，在 expires_at 前一小时推进隔离业务时钟后重新登录，并保留浏览器页面持续可见。这里用实际时钟推进触发自然到期。
2. 在 expires_at−1ms 验证 /me、项目成员及任务读取仍有效、审核人可打开 V1、页面仍待指定审核可提交。保留旧 revision 与一个拟提交的有效 final_fail。推进到恰好 expires_at，保留同一登录，仍能读取项目和任务。使用同一页面与独立 HTTP 验证材料原文、私有标题、固定版本细节和受保护的审核正文不可读。当前任务应显示「待材料授权」，无须更改截止时间，不能显示为失败、退回或项目失权。条件允许时用既有测试 observer 保持一个真实 review 请求已到服务端但未送完请求体，再在到期时送完余下请求体，以证明提交事务再次检查材料权。
3. 到期后用已准备旧 revision 的失败裁决尝试结算，再用当前可见 revision 尝试、重放旧请求。当前材料缺失应得到受控拒绝。核对零新增或派生裁决、无成功收据、零新增改判或重算事件，原提交时间与截止比较未被改写。打开的新页面和已经打开的页面都应遵守正确提示；持续浏览页面先看到原素材再观察清退，截图与 API 对照均留证。根任务/历史仍按权限可见。用持续在籍但无材料授权的审核人作为正负测试主体，不以关闭浏览器、成员离场、账号超时或手动 revoke 代替自然到期。
4. 在 V1 不再是最新版本后由所有者发新材料授权，或按候选实际用户入口提供新的可读固定资料。从等待恢复到原审核阶段，不自动通过/失败，不漂移到 V2。若恢复同一 V1，刷新后按最新 revision 和 V1 固定标准提交真实裁决，并验证只有一条成功记录。若替换材料，原提交保留，替换生成新版本并按该版本审核。重启后权限和历史保持，过期旧邀请码不能重新授予权限。保留 PROJECT-002 的管理员终审权限与前台撤权回归。
