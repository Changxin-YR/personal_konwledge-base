# 第 1 包：冻结前独立测试契约

依据：3.4.0 唯一入口和任务包。初始状态全部 NOT_RUN。本文件不是验收报告。仅回环、合成身份、隔离目录、真实 Host 与 SQLite；不接入模型。待主管激活并通知冻结 SHA/树后运行，证据记录命令、退出码、PID、HTTP 和独立连接读取的数据库前后态，不保存原始令牌。实现和构建均只读。

|项|前置与刺激|失败判据（任一不符即失败）|
|---|---|---|
|T01|真实 Host 内领取并落盘 checkpoint=1；外部连接证实无结果或事件；强杀 Host 并确认退出，原目录重启。|新 PID，原任务保留 checkpoint=1，接管 attempt=2，仅再 step 一次即成功。旧尝试有失联原因和结束时间，结果及事件各一。只杀旁路 CLI 不算。|
|T02|同一用户以同键同参重复 POST；同键改成另一有效对象；完成后重复投递同一 event_id，再调 dispatch。|重放返回同一任务，变参须业务冲突；数据库一任务、一结果、一事件、一条绑定该事件的回执。GET 与数据库终态一致。|
|T03|两个独立进程分别打开连接，在就绪屏障后同时领取；真实租约到期，另一方接管。|只产生一个有效令牌、一次尝试；接管令牌不同。旧令牌 renew 和在检查点 0、1 的 step 均不得改变任务、运行历史或效果。新 worker 可完成。|
|T04|部分租期后续租，越过原截止点再竞争；停止续租并连续等待三次真实过期。|续租后未被抢占；尝试计数与每条起止、先后及失联原因正确；耗尽为失败、有原因、无结果事件，重复领取不复活。|
|T05|用独立任务推进至检查点 1；分别在写结果后、写 outbox 后但提交前故障。|观察到预期注入点，结果、事件和成功状态一起回滚；去掉注入后复试，成功且各一份。意外异常不能算通过。|
|T06|领取并落盘检查点后，分别取消、注销提交会话、撤销实际对象权限、更新输入 revision。另有正常控制。|先验证对应屏障已生效，用原令牌尝试提交；不得成功，业务结果和成功事件为零。|
|V6|固定基线生成带业务记录的 v5 库，记录版本、应用 ID、schema、账本、逐表数据摘要；独立进程注入 v6:after-schema，随后正常升级并重开。|失败后 v5 快照完整一致，无部分 v6 表。正常升级仅追加 v6，原账本、表结构与业务数据不变，新表齐全，重开无损。|

缺少冻结身份、依赖或未执行不得记 PASS。主管冻结后只对齐未指定的字段命名、故障点或 Host 手动驱动配置，不放宽以上判据。T07、T08 和模型验收不属本包。

第二次冻结前补充 T02：用未投递事件注入消费者故障；逐次检验尝试次数、可重试时间、回执数为零和未标成功。去除故障后只能有一条回执；连续失败达到上限后进入失败终态，越过下一重试窗口反复 dispatch 不再投递。消费者失败不得撤销已提交的任务结果或制造第二条业务事件。
