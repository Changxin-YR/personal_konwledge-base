# 实施与持续推进计划

目标是交付完整功能范围的可运行产品。M0–M6 是依赖顺序，后续里程碑都在首轮总体实施范围内。阶段完成后持续进入下一阶段，真实外部阻塞只阻塞依赖它的工作。

## 1. 执行方法

每个里程碑先列具体任务和验收 ID，再实现纵向闭环：界面 → API → 权限 → 领域服务 → 持久化 → 结果展示 → 故障恢复。共用契约先确定，独立模块可并行开发；数据库迁移、公共类型和上游适配由明确负责人串行整合。

需求矩阵的 `milestone` 表示主要实施归属，场景的 `final_milestone` 表示完整验收最早所在阶段；阶段子场景通过不得把完整场景提前标为 PASS。一项需求只有全部关联的必要场景都通过，才能标为 verified。

每次完成一个可验证切片，保存对应提交、命令和证据。进度表同时记录实现状态和验证状态。纯界面样例、内存假数据、假 GPT 响应不算正式业务闭环；开发夹具可以使用，但产品运行时显著标注或彻底关闭。

## 2. M0：上游集成、身份边界与最小工程

**产出：可以构建、启动和保存数据的 KnowledgeOS 插件骨架，真实接入路径明确。**

1. 保留用户工作树，读取本仓库与上游 AGENTS。创建 `codex/knowledgeos-m0` 分支，运行计划检查和源码准备脚本；记录系统、Node、pnpm、上游 SHA。
2. 在固定上游完成依赖安装与所需构建，先读取安装脚本和依赖构建允许列表。使用上游当前支持的启动命令，不臆造 `npm run dev`。
3. 建立本仓库 `packages/` 与 profile/Bundle 装配，锁定依赖与实际构建脚本。验证一个 Host 服务和一个真实 Client 面板，随后注册六个稳定入口及基本状态页。
4. Client 按 DSH 模块装载协议构建，不把普通 Vite 输出当可装载插件。验证加载、刷新、重载、卸载释放和重复注册；记录源码缓存与插件产物的可重建路径。
5. 用 `node:sqlite` 进行业务库建表、跨表事务回滚、重开持久化与并发写探针；若目标 Electron Host 不支持，依据实测选择兼容驱动并记录决策。不能把 DSH JSON KV 当事务库。
6. 建立个人身份与共享服务账户边界、请求上下文、授权检查和结构化错误。用两个账号、一份私人资料和一份项目资料证明隔离；客户端传入他人的 owner_id 无效。
7. 对专用共享 profile 做路由清单和未授权访问探针，确认默认 owner RPC、任意文件、Session 附件、插件管理、Shell/Terminal 等入口没有暴露给成员。可复用 RemoteAccess，但业务授权不能省略。
8. 验证一次 DSH 模型接入：保存真实 provider/model、请求上下文与用量；有凭据则实际调用默认 GPT，无凭据标 `BLOCKED` 并继续不依赖模型的功能。夹具另列。
9. 为 F30 预留受保护核心策略、持久任务与事件表；保护策略由服务执行，普通插件 UI 不可卸载/关闭。
10. 落实脚本：开发启动、目标构建、类型检查、针对性测试、迁移、备份、清理开发产物（不得清用户数据）。更新 README 的真实命令。

**通过条件：** 固定版本实际加载页面、写入重开后数据存在、A 账户不能读 B 的私人记录、共享端未知/危险路径被拒绝、日志可追溯。Windows 不可用时宿主 ABI/安装验证继续列为平台阻塞，不能凭 Linux 构建宣称通过。

## 3. M1：资料与阅读、来源与权限

**产出：可导入、阅读、搜索并准确引用的知识资料库。**

- 完成资料对象、不可变版本、原件与派生文件、对象 ACL、邀请码及审计基础。
- 导入 PDF、Word、Markdown、常见文本和压缩包；任务队列支持进度、取消、局部重试、崩溃重入。
- 转换结果转为永久知识资产，保留原件和质量报告。格式转换与阅读不能依赖原 Session 存活。
- PDF 页面虚拟化、目录、书签、批注、阅读位置恢复；部分解析可用时先读，未解析/待复核仍可见。
- 中文、英文、混合术语和代码标识符检索，引用精确回到版本/页/片段；建立固定可复现检索集。
- 真实权限过滤覆盖搜索、页图、摘录、引用、下载、异步解析和索引。授权到期、撤销、删除后立即限制后续访问。
- 对约 40 MB、730 页资料运行规模测试，记录设备、格式性质、处理阶段耗时/峰值内存/失败页。若只有自制资料，标明；拿到真实用户文件后补验，不能把自制样本称为用户教材。

**通过条件：** P02 与矩阵中 final_milestone=M1 的验收项走通；P13 只验证邀请码绝对到期与权限基础子场景，P14 只验证导入/草稿恢复子场景，完整场景留到后续阶段。首次可用章节无需等待整本结束，引用可人工回读定位，跨用户无越权。

## 4. M2：知识、笔记与完整训练闭环

**产出：阅读 → 术语/知识/笔记 → 遮挡/快答 → 个人错题 → 复习的日用闭环。**

- 术语卡、知识条目和轻量本体关系；关系必须有合法的起终类型、方向、证据与确认状态。
- 笔记统一节点数据，大纲和脑图双向操作；树结构/布局分开，父节点删除展示后代影响，不删除所引用原资料。
- 长文任意选择和跨页遮挡，保存引用版本与锚点、遮挡分组、提示/揭示/首次回忆和恢复位置，不能用固定短长度截断。
- 选择/判断/填空、基础快答、题目质量复核；共享题目和个人答案/错因/复测记录分开。
- 复习预算默认占每日计划学习时间 10%，可调整，超量待安排。改变学习方向需本人确认；已授权复习不每次追问。
- 建立软考入口与通用基础题型，提供独立表现与提示程度记录；完整案例分析、论文训练和模拟复盘归 M3。不得把模型评分包装为考试官方结论。

**通过条件：** P01、P03–P05 及 final_milestone=M2 的场景完整，两个用户做同题的历史彼此独立；页面刷新/重启不丢正式记录与草稿。P06 在本阶段验证复习候选与预算纯逻辑，统一计划与不重复计时的完整验收在 M4。

## 5. M3：仓库分析、工程能力与架构师训练

**产出：针对真实授权仓库的代码讲解、问题诊断和工程复盘。**

- 首先交付 GitHub，只读仓库/提交/文件快照；统一适配接口，并完成 GitLab、Gitee 的基础接入契约和有条件可测的真实只读路径，缺凭据明确标注。
- 从文件、模块、项目到关键业务流程逐级讲解，引用固定 commit/path/行范围；区分源码证据与推断。
- 工程训练按业务理解、问题发现、复现假设、定位、修复方案、修改验证、复盘迁移保存过程；首次判断不被后续 AI 建议覆盖。
- 默认不运行仓库脚本、不写远端。外部开发环境的修改/测试证据可导入，区分自述、日志、真实复验。
- 案例关联知识、术语和训练，管理员任务仍走正式审核；独立挑战采用逐级提示，记录辅助程度。
- 完成 F27 的案例分析、论文训练、模拟复盘与工程知识关联；按 A22 验收，不能只保留软考菜单入口。

**通过条件：** P07、A22 及 final_milestone=M3 的场景走通；至少一个经过实际复现/修改/验证的案例与一份不可验证案例呈现出不同状态，不把分析建议标为修复成功。

## 6. M4：计划、项目协作、评分与 F30

**产出：可由约 10 人实际协作使用的任务和学习管理闭环。**

- 项目成员、邀请、任务派发、依赖、提交版本、同伴预审、管理员终审、退回/再提交、复议与改判。
- 共享服务统一确认任务状态；界面清楚展示下一处理人。管理员派发任务没有管理员终审不能正式通过。
- 今日计划、复习预算、有限执行时段、等待审核、已认可阻塞、请假/休息、执行证据与不重复计时。
- ABCD 评分采用已记录版本的规则；待审/争议影响档位时暂缓结算。评分更正触发计划日序列与提醒重算。
- F30 策略在领域层实现，规则固定启用，按约定时段合并提醒；多窗口/重启/断网不重复发送，不补发历史积压。
- 提交、同意、改判、授权失效、评分重算都有幂等与事务行为。会员数小也不能靠前端串行避免竞争。
- 运行多人并发验证：至少 10 个独立身份的授权/提交/读写混合场景，报告样本与时长，不把 10 个请求当 10 位真实用户长期试用。

**通过条件：** P06、P08–P11、P14 完整提交/恢复流程和 final_milestone=M4 的场景通过；C→待审→D 不能拼接，改判取消无依据提醒，“开始”不能永久免催，管理员改判审计完整。

## 7. M5：多智能体讨论、AI 动作与插件管理

**产出：可追溯、有终止条件的方案讨论与平台操作。**

- 主 GPT Agent、评审席位、阶段、最多五轮、候选稿哈希、材料版本、意见处理、投票和冻结。
- 全部预先指定席位有效完成 + `ceil(2N/3)` 赞成 + 重大阻断已处理才到冻结条件。调用失败不是弃权；不能为凑票临时缩小分母。
- 超时/取消/额度不足形成可恢复任务；候选稿更改使旧票留在旧版本。第五轮未通过交给用户裁定，不自动进入下一阶段。
- AI 提供资料导入、计划、题目与已授权平台动作；预览、权限、动作幂等和审计共用人工 API。
- 插件安装/启用/停用/移除通过受控管理流程，区分普通可选插件和不可关闭的产品核心。新 Host 插件需可信来源、版本锁和相应管理授权；不把模型建议视为授权。
- 展示真实用量，未知价格显示未知；不要用当前 ChatGPT 对话或套餐推断可用 API 额度。

**通过条件：** P12、M5 相关项以及真实模型讨论走通；缺真实 provider 的场景保持明确阻塞，其他状态机测试继续完成。

## 8. M6：生命周期、恢复、Windows 包与整体验收

**产出：可安装/升级/卸载、能备份恢复、附带可核验证据的候选版本。**

- 全面验证回收站 30 天与永久删除、引用/题目/评估失效、旧分享恢复需重新确认。
- 实现一致性备份、manifest、完整性检查、先预览再恢复；恢复不复活过期授权，权限/任务/附件/索引版本相互匹配。
- 故障演练：进程中断、断网、磁盘不足、迁移中断、模型超时、权限在任务中撤销；明确最终结果和重试责任。
- 实现 Windows 打包与安装流程，分别验证干净安装、二次启动、升级保留数据、回退可行性、卸载默认保留用户数据，以及选择清理的明确交互。
- 源码构建、核心端到端路径和 44 项覆盖核对；依据 Windows 真实环境生成截图/录像和测试记录。
- GitHub Releases 上传候选安装包、校验和与说明；源码中只存发布索引和必要脱敏证据，不塞二进制。

**通过条件：** P13 的删除/恢复/旧分享全流程完成，44 项实现与 66 个验收场景逐项有真实状态，关键权限/数据/提醒/审核门槛没有 FAIL；NOT_RUN/BLOCKED 不计入通过。产品最终由用户审阅后决定正式发布。

## 9. 并行分工和停止规则

M0 适配与认证边界没有验证前，其他模块可以完成领域纯逻辑、契约和 UI，但不得声称已集成。M1 的文件/权限基础先于 M2/M3；M4 评分/提醒依赖任务与学习正式结果；M5 投票状态逻辑可独立开发，但真实动作需要同一权限入口；M6 的备份/删除设计从 M1 开始，不留到最后补关系。

遇到没有模型凭据、真实大 PDF、Windows 测试机、签名身份等条件时，只暂停对应验证；提交当前成果、明确解除条件，继续独立任务。只有所有可执行路径都完成或都受到真实阻塞时才停止自主推进，并给用户一份最终报告。

不得用无限重试、切换低要求实现、放宽验收、删功能、跳过失败测试来继续。修复具体故障；对第三方限制记录证据，提出影响最小的替代方案。
