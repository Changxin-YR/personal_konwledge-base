## 1. 执行与证据规则

每项验收记录至少包含：场景 ID、被测源码提交、锁定的 DSH 提交、测试环境及版本、输入样本标识/哈希、身份与权限、步骤、预期、实际、结论、可定位证据、执行时间与时区。涉及模型的场景还记录真实提供商/模型、调用是否成功、能够获得的用量；敏感凭据及用户原文不得进入公开报告。

结论使用 `PASS / FAIL / BLOCKED / NOT_RUN`，不能把 `BLOCKED` 或 `NOT_RUN` 计为通过。需求层状态使用 `planned / in_progress / implemented_unverified / verified / blocked`。同一需求只有其必要场景均有对应范围的证据，才能标记 `verified`。

验证层级：

| 层级 | 能证明什么 | 不能据此替代 |
|---|---|---|
| integration | 权限、事务、状态、重试等可重复行为 | 真实模型、真实文件、真实平台安装 |
| e2e | 真实页面从入口到结果的操作闭环 | 无法接通的后端或外部服务 |
| real_fixture | 固定真实资料/代码上的行为与证据 | 用生成小样本冒充730页真实PDF |
| real_environment | 真实DSH、真实身份/模型/平台、Windows交付 | 夹具调用或静态UI截图 |

单元测试可作为上述验证的基础，但不单独替代集成和真实环境验收。历史上 FND-003 身份切片包含十二项测试与独立复核；A02/A03只覆盖身份/偏好子集，完整场景继续NOT_RUN。外部条件不足时记录具体阻塞、解除步骤及尚未证明的结论；形成有效检查点后，按当前持续协议选择不依赖该阻塞且前置已通过的下一单元。后期完整产品审查不能替代本阶段测试。

M0 按 FND 单元逐步完成真实 DSH 挂载、身份链及真实调用；FND-001 仅交付挂载/状态查询的子集，完整 A01 由 FND-005 负责。共享协作权限基础在 M1 前建立；M4 完成三身份和约十人场景的全面验证。权限、版本、断网与审计应随功能实现，而不是集中到最后补。

## 2. 验收输入与环境

- 三个独立身份：本人管理员、成员甲、成员乙；管理员只获得明确授权范围。约十人协作测试另准备隔离身份。
- 合法真实大 PDF（约730页、40MB）及可公开的小夹具；Word、Markdown、文本、ZIP；损坏页、混合表格/图片/代码等样本。
- 预先固定的中文查询和预期证据页；不能事后只挑命中的查询报告成功。
- 固定提交的真实测试代码仓库和可复现缺陷；GitHub可读取，GitLab/Gitee真实集成缺条件时分别报阻塞。
- 可控时钟用于评分、邀请和提醒边界；Windows隔离环境用于真实安装、休眠恢复和通知送达。
- 真实可用的已配置 DeepSeek 账户及用量记录；无凭据时应先完成适配器和夹具测试，再对真实调用明确报阻塞。

输入原件、密钥、令牌、个人学习记录和私有仓库正文不提交公开 Git。证据中优先保存脱敏摘要、哈希、版本、状态及合法可公开夹具。

## 3. 已确认主场景 P01–P14

### P01｜核心功能入口可发现

- 需求：F04、F10、F11、F12、F24；验证层级：`e2e`。
- 前置：用户已登录、有个人知识库。

- 预期：四个入口直接可见；目标页面可操作；两个入口使用相同对象与个人记录。
- 证据：真实 UI 截图/录屏、对象标识、操作结果。

### P02｜大 PDF 部分可用

- 需求：F05、F06、F07；验证层级：`real_fixture`。
- 前置：准备有权使用的约 730 页、40 MB 真实 PDF。
- 操作：导入全书；部分章节解析完成后打开阅读；观察剩余处理；取消并恢复部分处理。
- 预期：已完成章节可阅读；未处理与待复核分开显示；来源页与版本正确；最终结果与原件核对。

### P03｜术语到练习保留阅读位置

- 预期：解释与题目有来源；首次答案及辅助程度分别保存；甲乙个人表现互不影响；阅读位置恢复。
- 证据：测试记录、关键状态与操作证据。

### P04｜跨页长文遮挡恢复

- 证据：完整选区与原文范围比对、录屏、持久化记录。

### P05｜错题、不确定与争议分流

### P07｜工程诊断完整证据链

- 预期：首次表现不覆盖；每次提示可回看；验证关联准确提交/命令/结果；修复与迁移结论各有依据。

### P09｜待结算不能拼接低分

- 需求：F30；验证层级：`integration`。

- 预期：初始不触发；结算C后满足连续三低分；结算B后不满足；争议日不被跳过。

### P10｜执行时段有限与逐任务豁免

- 需求：F28、F30；验证层级：`integration`。

- 操作：开始第一项有限执行时段；到期不交成果；认可其外部阻塞；查看第二项。
- 预期：规则始终启用；执行状态到期重新判断；第一项阻塞不豁免第二项；不可永久挂起。
- 证据：测试记录、关键状态与操作证据。

### P11｜复议改判修正提醒与结论

- 需求：F30、F35、F44；验证层级：`integration`。

- 预期：原裁决和已发提醒留档；日评分、序列、项目进度重算；失去依据的待发提醒取消；案例标记复核。
- 证据：测试记录、关键状态与操作证据。

### P12｜两赞成一调用失败

- 需求：F38、F39、F40；验证层级：`integration`。
- 前置：三个固定评审席位、同一候选版本。
- 操作：两席赞成，第三席调用失败；重试后产生有效反对且没有未处理重大阻断。
- 预期：失败时受阻不能冻结；全员有效评审后重新按2/3门槛判断；失败不算反对或弃权票。
- 证据：受控错误测试及至少一次真实多席调用证据、版本和席位结果。

### P13｜邀请与删除恢复不复活授权

- 需求：F32、F41、F44；验证层级：`integration`。
- 前置：七天邀请，第六天兑换后被分享资料进入回收站。
- 操作：恢复资料；越过原第七天截止；再次尝试旧分享与权限。
- 预期：恢复先预览；旧分享须重新确认；授权到原截止即失效；过期或撤销授权不会恢复。
- 证据：测试记录、关键状态与操作证据。

### P14｜断网恢复无重复入账

- 需求：F24、F29、F42；验证层级：`integration`。
- 前置：一次训练提交或任务提交在远端成功，但客户端未收到响应。
- 操作：断网并重启，再联网重试相同操作。
- 预期：草稿和原结果保留；先核实服务端结果与权限；仅一次作答/提交/评分，不重复记时。
- 证据：故障注入点、幂等标识、前后记录数、恢复截图。


## 4. 补充场景 A01–A52

### A01｜真实 DSH 挂载和一次调用

- 需求：F01、F37、F40；验证层级：`real_environment`。
- 前置：锁定官方上游完整提交；测试账户与真实模型凭据可用。

- 证据：各读取路径拒绝结果、缓存/索引处理证据。

### A47｜断网草稿和授权变化

- 需求：F42、F44；验证层级：`integration`。
- 前置：用户编辑中断网，期间服务端撤权或他人更新。
- 操作：离线继续草稿，联网后同步。
- 预期：草稿保留；先验证当前权限和版本；冲突可处理；不能用旧授权自动提交/覆盖服务端内容。
- 证据：测试记录、关键状态与操作证据。

### A48｜导出与备份恢复

- 需求：F43、F44；验证层级：`real_environment`。
- 前置：两身份混合资料，含版本/引用/训练/任务，授权状态不同。
- 操作：各自导出；创建备份；在清洁环境恢复；检查关联、冲突与撤权对象。
- 预期：只导出有权内容；恢复后可读可定位且记录一致；已撤销授权不复活；密钥不进入明文仓库；输出恢复报告。
- 证据：导出范围、备份哈希、清洁环境恢复记录、关系/权限校验。

### A49｜Windows安装升级卸载

- 需求：F01、F42、F43；验证层级：`real_environment`。
- 前置：Windows隔离测试环境、可还原快照、候选安装包和已有用户数据。
- 操作：安装运行，升级，失败回退，卸载后按约定处理用户数据；检查离线重启。
- 预期：可实际启动与使用；升级迁移不丢数据；回退边界明确；未实测步骤不写PASS；发布包可校验且对应源码提交。
- 证据：系统/包版本、SHA256、安装与升级记录、数据前后比对。

### A50｜两级导航与风格验收

- 需求：F01、F04；验证层级：`e2e`。
- 前置：六工作区均有可操作页面。
- 操作：遍历所有入口与子页，在常见Windows窗口尺寸和缩放检查；展开阅读/AI面板。
- 预期：最多两级应用导航；子页归属清晰；四核心入口显著；无三个常驻侧栏；字体/冷玉青/适度圆角一致。
- 证据：全入口截图、窗口尺寸/缩放、交互录屏。

### A51｜约十人协作与竞争更新

- 需求：F01、F31、F33、F34；验证层级：`real_environment`。
- 前置：约十个隔离身份、不同项目范围与并发审核/编辑。
- 操作：并发读取提交与竞争修改同一任务，单身份离线后重试。
- 预期：身份与项目不串；冲突可见；不能双重终审/重复计分；记录实际响应情况，不宣称未测并发容量。
- 证据：身份/权限配置、竞争操作轨迹、最终记录一致性。

### A52｜全生命周期端到端闭环

- 需求：F02、F20、F28、F37、F44；验证层级：`real_environment`。
- 前置：真实上游运行、真实资料、真实模型、三个协作身份、固定代码提交。
- 操作：导入阅读→术语/笔记/练习→复习→工程训练→提交终审→评分提醒→讨论冻结→版本更新→导出恢复。
- 预期：全部环节可回溯同一对象和证据；权限、版本、个人表现和状态贯穿一致；每个外部依赖均有真实成功证据或明确阻塞。
- 证据：全程录屏/运行报告、来源/模型/提交/版本标识及恢复结果。

## 5. 交付门槛与报告模板

每个阶段保存一份验收报告，正文先写实际结论与未通过项，再列证据。目录结构以主实施计划规定为准。报告建议格式：

```text
被测代码提交：
DSH锁定提交：
环境与测试时间：
本阶段需求：
PASS / FAIL / BLOCKED / NOT_RUN 数量：

场景ID：
输入与身份：
执行方式：
预期：
实际：
结论：
证据位置：
失败/阻塞原因：
恢复或补测步骤：
```

最终交付须同时核对：所有44项有实现位置；66场景有执行结果；真实来源和模型链路已验；权限和生命周期闭环成立；Windows包对应实际源码提交并有SHA256；安装、升级、回退、恢复结果分别如实列明。不能把“文档已写”“UI已出现”“构建成功”或“少量测试通过”汇总成全量产品通过。

如暂时缺乏真实大PDF、外部平台凭据、模型账户或Windows隔离机，可以交付可审查的代码和已验证部分，但最终产品结论必须明确保留相关未验证项；分阶段推进不能将这些要求从矩阵删除。
