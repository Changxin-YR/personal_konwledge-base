- 文档版本：1.0（2026-11-16，Asia/Shanghai）
- 适用项目：`Changxin-YR/personal_konwledge-base`
- 上游：`deepseek-ai/deepseek-harness`，实际锁定提交以仓库的上游能力审计与锁定文件为准。
- 状态：**功能设计基线；所有实现与运行验收仍待真实证据。** 前序“44/44 通过”仅表示需求覆盖和规则一致性核对通过。

## 1. 范围与决策优先级

KnowledgeOS 面向本人及不超过约十人的小型协作，Windows 桌面端优先。首批覆盖软件工程、系统架构、硬件工程、AI 开发，服务独立工程能力训练、系统架构设计师备考、长期私人知识积累三类目标。以已核实的 DSH 能力为基础扩展，避免将公司 Mandate、记忆沉淀或数字员工图编排项目的能力误当作本上游已有能力。

产品形态为一体化平台。资料、知识资产和训练材料进入知识库；原创笔记独立；私人使用与项目协作同时成立。注册登录、个人空间、用户目标及项目成员权限属于正式范围。功能分期实现不表示从最终范围删除后续功能。

决策顺序：用户本轮及此前明确确认的规则 ＞ 本文件中“已确认”的需求 ＞ 实施契约与架构决策 ＞ 有明确标记的实施默认值。遇到两个已确认条款冲突，应记录冲突并采用较新的明确决定；不能凭空删改需求。

## 2. 信息架构与界面要求

### 2.1 六个工作区

| 一级工作区 | 二级功能范围 |
|---|---|
| 今日计划 | 今日任务、今日复习、背诵任务、基础快答、执行记录、ABCD 评分、提醒 |
| 知识库 | 资料与阅读、专业术语、知识条目、本体知识图谱、基础快答、题库、个人错题库、遮挡背诵、仓库与代码分析、工程案例、正式方案 |
| 笔记 | 普通笔记、层级大纲、思维导图、读书笔记、项目随记、个人复盘 |
| 项目协作 | 项目成员、任务、提交、审核、复议、进度、协作记录 |
| 智能讨论 | 探索讨论、阶段评审、方案版本、意见处理、投票、冻结成果 |
| 管理与设置 | 用户与权限、模型、插件、管理员统计、通知、回收站、导出与备份 |

知识库首页必须直接显示 **专业术语、遮挡背诵、基础快答、错题复习**。不得仅把这些能力藏在 AI 聊天菜单中。今日计划引用这些功能的同一份记录。

全局入口包括可见范围切换、统一搜索、创建、消息中心和按需展开的 AI 助手。助手显示实际使用的资料、页段、版本、权限范围，并可跳回来源。

### 2.2 导航与视觉约束

- 应用导航最多两级：一级工作区和该工作区的子页。切换一级入口后，主内容及子入口均属于该入口；不得累积三层以上常驻侧栏。
- 页面以清晰的上下层级组织，避免多块同权重左右面板互相挤压。阅读目录、AI 辅助、筛选或属性可按需展开；同屏不同时堆叠多个辅助栏。
- 导航层级限制不等于禁止笔记大纲、章节目录或知识树本身拥有多级内容。
- 简洁温润、冷玉青色调；不能回到此前被否定的鲜绿色大面积铺色。默认用系统企业常用字体栈（Windows 优先 Segoe UI / Microsoft YaHei UI 等），适度圆角、清楚对比和留白。
- 同一对象在列表、大纲、脑图、项目和今日计划中使用同一标识，视图切换不能复制内容或产生不同状态。
- 当前没有可核对的完整参考图片资产时，只能实现上述文字约束并提供实际截图验收，不能宣称已经逐像素复刻此前原型。

## 3. 核心对象、归属和证据

| 对象 | 归属 | 关键规则 |
|---|---|---|
| 原件、解析页、章节、仓库快照 | 知识库 | 原件保留；版本不可悄悄替换；解析范围与问题可见 |
| 术语、知识条目、本体关系 | 知识库 | 带领域、类型、证据、来源版本、确认状态 |
| 题目、答案、解析、背诵材料 | 知识库 | 共用正文与个人表现分开；来源有变化时待复核 |
| 作答、错题、提示、背诵表现 | 每人独立的训练记录 | 个人隔离；首次表现保留；管理员须有相应查看授权 |
| 普通笔记、大纲、脑图 | 笔记 | 同一内容的不同视图；删除引用不删除知识库原件 |
| 任务、提交、审核、复议 | 项目协作 | 提交与标准版本绑定；下一处理人明确 |
| 日计划、执行时段、日评分 | 今日计划 | 引用任务与训练；不重复计时；评分可追溯 |
| 讨论、评审席位、投票、方案版本 | 智能讨论 | 投票绑定版本；冻结与实际验收分别成立 |
| 冻结正式方案、确认工程案例 | 知识库 | 关联原过程与证据；失效或改判产生复核标记 |

一个来源引用至少可定位到来源标识、来源版本、页/章/文件路径、片段或范围以及可复现的定位信息。代码引用还应绑定仓库和提交。动态行号、当前 HEAD 或自由文本书名不能单独作为可复现依据。

长期记录保留正常知识、笔记、学习记录及其必要历史。**三十天不是正常内容的保留期限，只用于回收站。**

## 4. 资料、阅读与知识积累

### 4.1 导入与转换

支持 PDF、Word、Markdown、常见文本及压缩包。对约 40 MB、730 页、文字为主夹少量图片的 PDF，支持整本与拆分导入；压缩包可选择内部文件。记录来源、归属、领域、可见范围、是否为新版本。

接收、解析、质量和可用性分别表达：已接收不等于解析完成；部分章节可用不等于全本通过；解析失败和待复核不能伪装成无内容。允许先阅读已完成章节、局部重试和继续处理，保留可恢复进度。

格式转换保留原件，生成独立结果供预览和核对，明确缺失、表格、图片、代码等问题。转换结果不得覆盖原始证据。大文件处理需避免一次性占满 UI 主线程或内存。

### 4.2 阅读与术语

阅读支持目录、搜索、书签、批注、位置恢复和原页定位。选中文本直接提供“解释术语、记笔记、遮挡背诵、基础快答”，执行后不丢阅读位置。

术语先解释当前语境，再提供通俗说明、专业定义、易混概念、来源、个人补充、练习与复习。临时查词不强制入库；形成正式知识条目时记录来源与确认状态。

### 4.3 遮挡与快答

支持鼠标选择任意长文片段，包括跨页长选区；不能用隐含短字数限制替代要求。保存完整选区及遮挡分组，允许分页练习；记录材料版本、原页范围、提示、揭示、独立回忆与自评；重新打开恢复组合与进度。

基础快答无需先组一套完整试卷，支持当前段落、章节或术语范围、可调整题量。先保存首次答案，再显示解析及来源。来源不足或题目有争议时可练习但不进入正式能力结论。

### 4.4 本体与笔记

轻量本体约束对象类型、关系类型、方向及适用领域；例如“解决、依赖、对比”等关系不能由 AI 随意创造无约束边。AI 建议带证据和待确认状态；人工可确认、纠正、拒绝与复核。不能把“模型提过”当作关系成立的证据。

笔记大纲与思维导图是同一数据源的两个视图，双向编辑同步。删除节点须展示对子节点的影响，引用移除不删除原件。个人私有笔记与项目笔记权限分开。

## 5. 训练、工程实践与长期反馈

题型至少包含选择、判断、填空。题目共用部分与每人的答案、错因、提示程度、复习状态分开。支持答错、答对不确定、提示后完成、题目争议等不同状态，不能用单一对错掩盖差异。

个人错题库独立管理错误原因、状态、复习进度与延后复测。每天默认使用计划学习时间的约 10% 复习，可调；超额内容按优先级待安排，不自动挤占已承诺项目任务。学习方向调整必须本人确认，采用小幅调整；既定授权范围内的复习排程可以自动执行。

工程训练从业务理解、发现问题、复现与假设、定位原因、设计修复、修改验证、复盘迁移逐步记录。独立挑战先保留原始作答，再给分层提示，记录假设变化和证据。默认仓库只读；可导入外部开发环境中的修改和验证证据，但不能因为有一段代码或一张通过截图就宣布实际项目已修复。

代码分析覆盖文件、模块、项目和关键业务流程；GitHub 优先，同时在接口和对象模型中考虑 GitLab、Gitee。第一次即可提供统一仓库适配边界；没有某平台的真实凭据时应报告该平台集成待验证，不得伪报支持通过。

架构师训练包含知识学习、案例分析、论文训练与模拟复盘。能力评估结合独立作答、提示程度、复测和迁移表现；自评与已验证事实分开。反馈能跳转到答题记录、工程证据和历史结论，并注明数据不足之处。管理员的业务裁决与模型的能力推断是不同记录。

## 6. 协作、权限、审核与评分

### 6.1 权限与邀请

个人空间默认私有。项目成员资格、内容可见范围、内容编辑、内容管理、审核权限、个人学习记录查看权分别控制。文档编辑权不自动包含删除原件、邀请他人、改变分享范围或管理权限。

邀请显示内容、权限和绝对截止时间，默认生成后七天。**第六天兑换只能得到剩余一天，不重新起算七天。** 邀请与该邀请产生的授权在同一时刻到期；续期、撤销均有记录。协作成员的个人训练记录不因加入项目自动全部公开。

每次读取、搜索、导出、训练取材、模型工具调用和后台处理都需按实际用户权限过滤；不能仅依靠 UI 隐藏。权限到期或撤销后，受控正文、答案、引用预览、检索缓存和 AI 取材按当前权限限制。断网保留用户已有草稿不等于可以无限使用他人受控资料；本地已知的绝对到期时间仍须执行，无法确认共享授权时采用受限或待核验状态，恢复后重新核验。

### 6.2 任务与审核

任务包含目标、验收标准、期限、负责人、审核路径。执行记录、阻塞、提交版本和审核记录分别存储。页面显示下一处理人。管理员派发任务：提交 → 可选同伴预审 → 管理员终审；同伴通过不代表正式完成。其他任务由事先指定审核人按约定裁定，管理员可在授权范围纠正。

退回必须指出未达标准、依据、补充内容和下一处理人。重提形成新版本。逾期、退回、受阻与失败分开；审核迟到不能篡改实际提交时间。标准改变保留版本并明确适用提交。审核材料权限失效时进入等待授权，不能直接判成员失败。

复议附着于原裁决；管理员改判保留原记录。改判后重算任务状态、项目进度、日评分、低分序列、待发提醒及受影响的正式案例。已发送提醒留档并注明依据更正，不能删除历史伪装成未发送。

### 6.3 今日计划与 ABCD 评分

显示今天承诺任务、现在可行动任务、复习安排、待他人或外部条件事项；计划考虑时间预算与前置条件。实际执行时长与成果只记录一次，即使同一任务同时在项目和学习视图出现。

评分依次进入待记录、待结算、已结算；影响评分的复议进入争议中。未定关键结果足以改变档位时暂缓结算。已确认的休息日、批准请假不计入低分序列；缺失记录不能擅自算成 D。

**评分公式与分档阈值尚未由用户具体给定。** 实施者应提供透明且有版本的默认评分规则，明确其为实施默认值，在计划承诺时展示并固定当日规则；默认计算可参考按事先约定权重计算的成果达成率，不能仅以在线时长决定档位，也不能把临时 AI 感觉作为结算依据。默认阈值若采用 A 为 90%–100%、B 为 75%–不足90%、C 为 50%–不足75%、D 为不足50%，必须标为可调整的实施默认值并有相应测试，不得冒称用户确认。后续规则调整不静默重写历史；历史更正走记录完整的重算。

### 6.4 F30 不可关闭强提醒：唯一正式规则

1. 规则在应用内固定启用；个人设置、AI、插件或普通管理操作均无关闭、暂停或退出该规则的入口。
2. 连续三个已结算的计划日均为 C 或 D，才满足低分触发。A/B 中断序列；休息日、批准请假排除；待结算或争议日不能跳过后拼接前后低分。
3. `C → 待审核 → D` 不成立；中间结算 C 后形成三个低分，结算 B 后不成立。缺少历史或乱序补结算必须重算，不能直接累加计数。
4. 实际发送还需当前在已约定学习/工作时段内，并存在当前可行动的未完成事项。提醒内容包含可开始、拆分、求助、报告阻塞的入口。
5. 有效执行、已提交待审、认可的外部阻塞、批准请假、休息或非提醒时段由系统按状态暂不发送。某任务受阻不豁免其他可行动任务。
6. “开始执行”绑定有限执行时段；结束后依据进展、成果或阻塞重新判断。仅点击开始不能永久逃逸提醒；不采用键鼠监控证明学习。
7. 进入可发送状态时提醒一次，此后距上次实际发送至少一小时再合并提醒。短时间多任务、多事件、重启和多窗口不能重复发送。恢复联网、跨时段或补结算历史不补发积压通知。
8. 当前可行动事项已经完成，或评分更正后不满足触发，系统结束对应催促。规则本身仍启用。
9. 保存触发依据、规则版本、发送时间、内容及结束原因。显示只读状态与原因，不展示关闭开关。
10. 约定时区和提醒时段是产品配置；初次使用须明确设置，不能虚构用户已经约定了具体钟点。实现默认可为 Asia/Shanghai，但应显示并允许按日历计划设置；不得用“每小时”推导全天通知。
11. 应用关闭、系统休眠或操作系统通知权限受限时的实际送达能力须如实显示；应用内规则不可关闭不等于强行拦截系统退出、规避 OS 权限或保证关机送达。

## 7. AI 操作与智能讨论

助手可以操作已授权流程，包括资料导入、题目、计划以及插件安装、启用、停用、移除。操作结果记录在具体业务对象中，保持身份、权限、幂等及可追踪；自然语言指令不能绕过管理权限或改变 F30 固定规则。对需要用户确认的学习方向变化，模型不能自行替用户同意。

DeepSeek 为主 Agent，其余评审席位负责批判、建议和投票。实际采用账户当前可用模型及默认限制；展示调用状态、模型与可获得的用量。无需伪装不同席位就一定是不同模型或独立主体。

每阶段最多五轮，主方案与评审都绑定明确版本。默认三个席位；正式通过需 **全部既定席位完成有效评审、赞成票 ≥ ceil(2N/3)、重大阻断问题已处理**。两票赞成、一席调用失败时仍受阻。有效反对意见不等于调用失败；两票赞成、一票有效反对且无未处理重大阻断时可达到门槛。

修改方案产生新版本，旧投票不能自动沿用。第五轮未达标转为待用户裁定，保留最佳稿与分歧；不得自行降门槛、缩减席位、继续第六轮后宣称同阶段通过。重试传输失败不新增成功评审，也不允许无限重试。

冻结阶段产物保留历史，重大变更回到相应阶段。最终确认的正式方案进入知识库；任务建议进入草案，由有权人发布。投票通过不替代任务验收，也不证明代码执行或修复成功。

## 8. 资料生命周期、网络恢复和备份

删除先展示引用、题目、背诵、项目等影响。进入回收站后停止普通访问与旧分享；三十天内支持还原，期满按明确范围清理。正常内容不自动三十天删除。恢复时展示位置、重名、权限、关联恢复情况；过期或撤销授权不复活，旧分享需重新确认才开放。

来源新版本保留历史，提示受影响的引用、题目、遮挡、知识关系和代码分析复核；不能悄悄移动历史提交的证据。来源失权、删除或永久删除的引用呈现准确状态。独立原创笔记不因引用失效整篇删除，但不得通过笔记引用或缓存绕过来源权限。

断网时保留页面、草稿、已完成结果和待处理远程操作。恢复后先核实原操作结果与当前权限，再续做；同一次训练、提交、评分或提醒不能重复入账。不可获得的远端材料显示受限或等待，不伪造完成。

按权限导出和备份，包含必要关联与版本。恢复有预览、冲突策略和验证报告；不得恢复已撤销授权或覆盖新数据而不记录。备份材料中的密钥与用户私密内容不得进入公开 Git 仓库。正式安装包、校验值和发布说明应进入项目明确的发布位置，并区分构建完成、安装通过与全量验收通过。

## 10. 实施完成的最低表述标准

每项需求至少对应一个真实验收场景和证据入口。`planned`、`in_progress`、`implemented_unverified`、`verified`、`blocked` 等状态不得混用。文档检查通过只验证文档；单元夹具通过只验证所覆盖逻辑；模型真调用、真实文件、真实多人账户、Windows 安装需各自证据。

产品入口可见、API 返回成功或模拟演示都不足以声明整个功能完成。若外部环境阻塞，应保留已完成部分、记录具体阻塞及解除步骤，只继续当前已激活单元内可独立开展的工作，不伪报通过，也不擅自转入其他功能。
