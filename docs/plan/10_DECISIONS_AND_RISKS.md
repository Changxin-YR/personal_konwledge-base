## 2. 仍需确定的可配置参数

- **ABCD 公式：** 用户确认要有等级和依据，没有给出完整加权公式。使用需求基线提出的可选默认值时必须展示、绑定版本并支持评审；正式数据不能在未告知规则的情况下被追溯扣分。按验收结果与承诺任务权重计算，不用键鼠时长判断努力程度。
- **提醒钟点：** 用户确认按约定学习/工作时段，未给本产品每日具体钟点。首次设置规划时段并明确展示；不得擅自套用实习作息或全天提醒。时段配置不能变成关闭强提醒的后门：有计划的工作/学习日必须有有效时段；修改留记录并说明生效范围。
- **执行时段：** 默认使用该任务本次计划的结束时刻；可提供合理短时默认值，但延长需要具体进度/计划更新，不能无限自动续期。
- **模型并发/预算：** 以实际 provider 和账户限制为基础，采用保守队列；不要编造固定免费 token。缺少价格只显示未知。
- **文件/压缩包限额：** 至少满足已确认 40 MB/730 页用例；额外展开大小、文件数和嵌套限额在配置中明确，并用超限测试证明错误可恢复。

这些参数只在对应工作单元激活后形成产品默认值。需要用户选择的是实际个人偏好或影响既有承诺的规则变更；开发可以在当前单元内使用明确标注的测试配置继续。当前 FND-003不涉及评分、提醒、资料文件限额或模型预算；身份v2迁移、密码/会话/防伪/限流和输入限制在唯一CODEX_START及当前工作单元明确，属于工程默认值。

## 3. 真实风险与对应门槛

| 风险 | 事实或设计原因 | 处理与验收 |
|---|---|---|
| 外部 Client 插件不能直接加载 | DSH 使用专有模块装载产物，构建 preset 依赖上游脚本 | FND-001 真加载、Host读取、失败与重载检查，不用静态截图代替 |
| 多人泄露私人内容 | 默认浏览器/Desktop 认证共享 owner 语义，部分附件接口为存储级 | 独立身份/对象 ACL/非白名单路由拒绝，两个身份与撤权测试 |
| 安装后 SQLite/转换依赖失效 | 源码和 Electron 打包 Host 的环境不同 | 打包后持久化、转换、资源路径探针 |
| 强提醒通过普通插件被关闭 | 上游 Schedule 可停用，Host 插件能运行进程内代码 | 产品核心保护 + 管理API/AI工具拒绝关闭，可信插件名单 |
| 资料变动导致引用或评分漂移 | 来源可更新/删除/撤权 | 版本不可变、依赖失效事件、历史保留、当前可见性复核 |
| 模型调用失败被误计票 | 真实网络/额度不稳定 | 每席状态、冻结版本、完整分母、失败受阻和恢复测试 |
| 断网或进程崩溃重复提交 | 服务器与客户端不能总是同时知道结果 | 幂等键、命令查询、outbox、有限重试、unknown 状态 |
| 备份恢复复活旧分享或重复提醒 | 备份可能早于撤销/发送记录 | 恢复预览、当前授权复核、旧实例关闭、恢复后重新结算 |
| 多智能体同时写同一功能导致证据失配 | 共享工作树变化可能发生在测试之后 | 一个实现者负责写入，测试/审查绑定候选提交；代码变化重跑受影响测试 |
| 目标架构被误当一次性开发清单 | 旧方案按大里程碑连续推进，易一次铺开多模块 | 只按当前激活单元读范围；FND-003只增加身份切片，不含完整ACL/六页/模型 |
| 只靠提示词中“已测试”作结论 | 模型可能总结未执行动作，或引用别的提交结果 | 证据记录命令、退出码、输入性质、运行结果和被测提交，不凭投票替代测试 |
| 当前修复被推迟到后期全面审查 | 完整审查可能被误解为当前无需验收 | 当前 Codex 接管完成已有基础修复和验证；后续每功能当时测试，完整审查另行激活 |

## 4. 运行能力与信任边界

应用内不可关闭 F30，不包含拦截操作系统退出、关机或修改源码。可信 Host 插件有进程级能力；仅靠普通 ACL 不能隔离恶意插件。共享服务不接受普通成员安装任意 Host 代码，管理员安装新插件也要可核对来源与版本。

已下载到外部的文件不能因邀请码到期被远程抹除；产品应限制后续访问和导出，展示实际分享范围。离线保存个人草稿与继续访问已失效共享资料是不同问题。

## 5. 单元内决策与阶段门槛

当前单元的设计检查至少列明需求映射、涉及的层/模块、具体数据或接口变化、正常/失败/边界用例、受影响的已有回归。通过该检查只允许实现当前单元，不授权整阶段自动展开。架构角色不通过反复提出新架构扩大范围，实现角色也不能用“顺手补基础”提前做多个功能。

FND-001 已交付真实加载的主面板与 Host 只读状态，以及对应失败和生命周期验证。FND-002持久化与保护已验收。当前FND-003在该基础上增加本机身份、个人空间和偏好；共享服务、模型路由、完整界面仍分别待激活。不能为任一基础切片提前要求全部 M0 义务，也不能因为单元通过就把 F01/F42 或关联完整验收全部标为完成。

开发多智能体可以在当前功能内分别进行架构检查、实现、测试和审查，当前候选代码只能有一个整合写入者。测试绑定代码提交/工作树摘要和实际命令；修复后重跑有影响的检查。任何角色的口头同意都不能替代运行结果。当前单元无法验证时如实记 NOT_RUN/BLOCKED，并仅处理该单元内允许的替代路径。

Codex接管已完成，用户最新指令已授权下一步，当前CODEX_START.md仅激活FND-003身份闭环。完整产品审查仍须达到实施计划定义的条件并由用户另行激活，不作为拖延当前修复的理由。

## 6. 变更记录格式

每次调整写明：编号、日期、当前单元、影响需求、原决定、当前决定、代码/实验依据、迁移影响、回退方式、需补的验收 ID。当前单元内的常规实现选择可以自行完成并记录；改变已确认产品行为或跨单元推进时，先提交具体差异与建议，由用户决定。旧执行指令只保留在 Git 历史，当前工作树不保留会被误用的旧启动提示词。
